# re:sonance アプリ機能整理

## アプリの目的

楽曲を聴き、openDAWで編集し、変更案をGitHub PRとして提出し、変更前後を安全に聴き比べられる共同制作アプリ。

## 画面構成

### 1. Overview（トップ）

目的: 曲を知り、試聴と編集を開始する。

必要機能:

- 曲名、作者、説明、ジャンル、素材ライセンスの表示
- Night Transitの再生・停止
- 再生位置、音量、シーク
- 「編集する」「提案を見る」への導線
- レンダリングやAPI障害時の簡潔な状態表示

### 2. Editor（openDAW編集画面）

目的: ブラウザ内で曲を編集する。

必要機能:

- openDAWプロジェクトの読み込み
- 再生・停止・編集
- 編集状態の保存またはスナップショット取得
- 編集結果のプレビュー
- 「提案する」ボタン
- 未保存変更がある場合の警告
- openDAWの読み込み失敗・対象曲不一致のエラー表示

### 3. Proposal（提案作成）

目的: 編集内容を説明付きで提出する。

入力項目:

- 提案タイトル
- 変更内容の説明
- 変更した時間範囲または対象トラック
- 任意の補足
- 使用素材とライセンス確認

処理:

1. スナップショットの存在とサイズを検証する。
2. `proposal/{proposalId}` ブランチを作成する。
3. `project/main.od` をコミットする。
4. GitHub PRを作成する。
5. PR番号、base SHA、head SHA、提出者を保存する。

状態:

- 入力中
- 送信中
- GitHub PR作成済み
- 失敗・再試行可能

### 4. Proposals（提案一覧）

目的: 提出済みの変更案を探す。

必要機能:

- 提案タイトル、提出者、作成日時、状態の一覧
- 曲ごとの絞り込み
- レンダリング状態の表示
- 提案詳細への遷移
- GitHub PRへのリンク

MVPでは投票・レビュー機能は含めず、一覧と詳細確認に限定する。

### 5. Proposal Detail（提案詳細）

目的: 変更内容の信頼性と音の違いを確認する。

表示項目:

- 提案タイトルと説明
- 提出者
- GitHub PR番号とリンク
- base SHA、head SHA
- openDAWコミット
- renderer version
- 使用素材、ライセンス、credits
- 作成日時、レンダリング日時

音声機能:

- 変更前音源の再生
- 変更後音源の再生
- A/B切り替え
- 同じ再生位置での切り替え
- 読み込み中、成功、失敗の表示
- 失敗時の再試行

### 6. History（履歴）

目的: 楽曲の変更履歴を追跡する。

必要機能:

- PRとコミットの時系列表示
- 提出者と変更概要の表示
- 採用・却下・オープンなどの状態表示
- GitHub履歴へのリンク

MVPではGitHubのPR履歴を表示元とし、独自の採用判定は後回しにする。

### 7. Files（素材・ファイル）

目的: 使用素材と権利情報を確認する。

必要機能:

- プロジェクトファイル一覧
- 音源・MIDI・画像などの種別表示
- `credits.json` の内容表示
- ライセンス名、作者、出典、利用条件の表示
- GitHub上のファイルへのリンク

音声ファイル本体はGitから直接大量配信せず、必要に応じてR2のURLを使う。

## 共通機能

- GitHubログインとログアウト
- ログインユーザー表示
- API通信中のローディング表示
- 成功・警告・失敗の通知
- モバイル幅でも主要操作が可能なレスポンシブUI
- キーボード操作と音声プレイヤーの基本アクセシビリティ
- GitHub、PR、コミット、素材への外部リンク
- 未ログイン時は試聴・閲覧を許可し、提案時だけログインを要求

## 状態モデル

```text
未ログイン
  ├─ 試聴・閲覧
  └─ 提案する → GitHubログイン

ログイン済み
  └─ 編集 → スナップショット作成 → 提案送信
                                  ├─ PR作成中
                                  ├─ PR作成済み → レンダリング待ち
                                  └─ 失敗 → 再試行

レンダリング待ち → レンダリング中 → 成功 → A/B試聴
                                └→ 失敗 → 再試行またはエラー確認
```

## MVPで必須の機能

1. Night Transitの試聴
2. GitHubログイン
3. openDAWの起動と編集
4. プロジェクトスナップショット取得
5. 提案作成とGitHub PR作成
6. base/head SHAの表示
7. base版・変更版の音源生成
8. A/B試聴
9. 提出者、PR、コミット、素材情報の表示
10. レンダリング中・成功・失敗の表示

## MVP後の機能

- 投票・レビュー
- タイムラインコメント
- 3人以上、賛成率3分の2以上、24時間締切による採用判定
- MIDI差分表示
- 派生作品作成
- 貢献履歴、クレジット、バッジ
- Discord通知
- 複数曲・複数プロジェクト対応

## 非機能要件

- Raspberry Piが停止していても、閲覧・試聴・低負荷プレビューは利用可能
- Piへの常時ポーリングを行わない
- GitHubトークンや秘密鍵をブラウザに渡さない
- 音源の重複生成を避けるため、proposal ID・SHA単位でキャッシュする
- APIに入力サイズ、レート、タイムアウトの上限を設ける
- 音声ファイルは静的配信またはオブジェクトストレージから配信する
